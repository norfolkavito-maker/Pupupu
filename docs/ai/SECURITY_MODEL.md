# Security Model

Этот документ описывает модель безопасности DedZapret Manager. Модель охватывает безопасность данных, процессов, системы и пользователя.

---

## 1. Основные принципы безопасности

### 1.1 Zero Trust Architecture
- **Никогда не доверяй** — все данные и процессы рассматриваются как потенциально опасные
- **Всегда проверяй** — аутентификация и авторизация для всех операций
- **Минимальные права** — принцип наименьших привилегий
- **Defense in depth** — многоуровневая защита

### 1.2 Security by Design
- **Security first** — безопасность учитывается на этапе проектирования
- **Privacy by default** — конфиденциальность по умолчанию
- **Transparency** — открытость процессов и данных
- **User control** — контроль пользователя над своими данными

---

## 2. Защита данных

### 2.1 Конфиденциальные данные
**Что защищаем:**
- API ключи и токены
- Пароли и учетные данные
- Приватные ключи сертификатов
- Персональные данные пользователей
- Логины и пароли proxy

**Методы защиты:**
- **Шифрование** — AES-256 для чувствительных данных
- **Маскирование** — замена чувствительных данных в логах
- **Ограниченный доступ** — только authorized процессы
- **Автоматическая очистка** — удаление после использования

### 2.2 Конфигурация
**Файлы конфигурации:**
- `config.yaml` — основные настройки
- `state.json` — состояние приложения
- `current.json` — активное состояние

**Требования:**
- **Чтение** — только приложение
- **Запись** — только с правами администратора
- **Шифрование** — чувствительные секции
- **Бэкап** — автоматическое создание перед изменением

### 2.3 Логи и отчеты
**Защита логов:**
- **Маскирование** — секреты заменены на ***
- **Ограниченный доступ** — только authorized пользователи
- **Автоматическая ротация** — сжатие старых логов
- **Безопасное хранение** — в защищенной директории

**Пример маскирования:**
```
Original: "Bearer abc123def456"
Masked:  "Bearer ***"
```

## 3. Защита процессов

### 3.1 Управление процессами
**WinWS2 процесс:**
- **Запуск** — только с проверкой прав администратора
- **Мониторинг** — отслеживание состояния и ресурсов
- **Остановка** — безопасная остановка с cleanup
- **Изоляция** — отдельный процесс с ограниченными правами

**Sing-box процесс:**
- **Песочница** — ограниченные права доступа
- **Валидация** — проверка конфигурации перед запуском
- **Мониторинг** — отслеживание сетевой активности
- **Изоляция** — отдельный процесс

### 3.2 Аудит и логирование
**Все операции логируются:**
- **Запуск/остановка** процессов
- **Изменение** конфигурации
- **Доступ** к чувствительным данным
- **Ошибки** и исключения

**Формат логов:**
```json
{
    "timestamp": "2026-05-07T04:14:00Z",
    "user": "user123",
    "action": "start_process",
    "component": "runtime",
    "success": true,
    "details": {
        "pid": 12345,
        "strategy": "v1-basic",
        "admin_check": true
    }
}
```

## 4. Системная безопасность

### 4.1 Права администратора
**Требования:**
- **Явная проверка** — is_admin() перед операциями
- **Пользовательское подтверждение** — запрос прав при необходимости
- **Аудит** — логирование использования прав
- **Минимальное использование** — только когда необходимо

**Операции требующие admin:**
- Изменение системных файлов (hosts, DNS)
- Запуск winws2.exe
- Установка автозапуска
- Изменение firewall правил

### 4.2 Сетевая безопасность
**Защита сетевых операций:**
- **Валидация доменов** — проверка разрешенных доменов
- **HTTPS** — все HTTP запросы через HTTPS
- **Certificate validation** — проверка сертификатов
- **Timeouts** — разумные таймауты
- **Rate limiting** — ограничение запросов

### 4.3 File System Security
**Защита файловой системы:**
- **Portable layout** — данные в DedZapretData
- **Path validation** — проверка путей
- **Access control** — права на файлы
- **Safe operations** — атомарные записи
- **Backup/rollback** — безопасность изменений

## 5. Безопасность пользователя

### 5.1 User Privacy
**Защита приватности:**
- **No telemetry** — нет сбора данных
- **No analytics** — нет статистики использования
- **Local only** — все операции локальные
- **User control** — контроль над своими данными

### 5.2 User Experience
**Безопасный UX:**
- **Clear messages** — понятные сообщения об ошибках
- **Actionable suggestions** — рекомендации по действиям
- **Confirmation dialogs** — подтверждение опасных операций
- **Progress indicators** — индикаторы выполнения

### 5.3 Error Handling
**Безопасная обработка ошибок:**
- **No sensitive data** — в сообщениях об ошибках
- **Error codes** — коды для поиска в документации
- **Help links** — ссылки на помощь
- **Safe fallback** — безопасные альтернативы

## 7. Защита от атак

### 7.1 Injection Attacks
**Защита:**
- **Input validation** — проверка всех входных данных
- **Parameterized queries** — параметризованные запросы
- **Output encoding** — кодирование вывода
- **Command injection** — защита от внедрения команд

### 7.2 Cross-Site Scripting (XSS)
**Защита:**
- **Input sanitization** — очистка входных данных
- **Output encoding** — кодирование вывода
- **Content Security Policy** — CSP headers
- **Safe rendering** — безопасная отрисовка

### 7.3 Cross-Site Request Forgery (CSRF)
**Защита:**
- **Anti-CSRF tokens** — токены защиты
- **SameSite cookies** — атрибуты cookies
- **Origin validation** — проверка происхождения
- **Request verification** — проверка запросов

### 7.4 Man-in-the-Middle (MitM)
**Защита:**
- **HTTPS** — все соединения через HTTPS
- **Certificate pinning** — закрепление сертификатов
- **HSTS** — HTTP Strict Transport Security
- **Domain validation** — проверка доменов

- **Pepper** — глобальный перчик
- **Storage** — защищенное хранилище

### 8.2 API Keys
**Хранение API ключей:**
- **Encryption** — шифрование ключей
- **Access control** — ограниченный доступ
- **Rotation** — регулярная смена
- **Revocation** — отзыв ключей

### 8.3 Configuration
**Хранение конфигурации:**
- **Encryption** — шифрование чувствительных данных
- **Backup** — автоматическое резервное копирование
